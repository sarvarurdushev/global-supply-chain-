# Architecture

Global Supply Chain Eye is God's Eye View plus a supply-chain intelligence layer. The
inherited application — Cesium globe, layer catalog, director, HUD, voice, provider tier —
is unchanged. The supply-chain work sits alongside it as a portable computation core with
its own sources and, in later phases, its own layers and panels.

See `docs/PROJECT_ARCHITECTURE_AUDIT.md` for what was inherited and why.

## Why the core is portable

Every module under `src/supplychain/` is registered as a portable export in
`scripts/package-boundaries.json`, and `scripts/check-import-directions.mjs` was extended so
that any export beginning `./supplychain/` is portable-checked. The gate mechanically
rejects any reach into Cesium, Node, or a browser global such as `document` or `window`.

That gives three properties the project needs:

1. **The analytics run under `node --test`.** Every result in this repository is
   reproducible without a browser or a GPU.
2. **The same code runs server-side.** A batch job can precompute a graph exactly as the
   browser would build it.
3. **Nothing in the analysis can quietly depend on rendering state.** A centrality figure
   cannot accidentally become a function of what is currently on screen.

## Separation of LIVE, HISTORICAL and MODELLED

This is enforced in code, not by convention:

- `createProvenance()` **throws** if a caller tries to class UN Comtrade, World Bank, IMF,
  OECD or NGA WPI data as `LIVE`. Those sources lag their reference period, so the badge
  would be a factual misstatement.
- `withScenario()` returns a derived view rather than mutating the graph, so a simulation
  cannot leak into the baseline.
- Every disruption and forecast result carries `dataClass: SIMULATED`, and every anomaly and
  inferred association carries `INFERRED`.

## Generated files

`src/supplychain/reference/comtradeAreas.js` and `commodities.js` are generated by
`node scripts/build-comtrade-codes.mjs` from Comtrade's published reference files, and
committed. The application never fetches reference data at startup. The generator is
verified to reproduce the committed files byte for byte.

## Testing

`npm test` runs the inherited suite plus the supply-chain suite in one pass. The
supply-chain tests are plain `node:test` with no framework and no network access — the
source clients are exercised through an injected `fetchImpl` against response fixtures
captured from the real APIs.
